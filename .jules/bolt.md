
## 2026-11-09 - Avoid Python interpreter startup overhead by replacing `subprocess.run` with direct module imports
**Learning:** Python scripts in `tools/` and `tools/validators/` were being called using `subprocess.run([sys.executable, ...])` inside the main orchestrator (`workflow_orchestrator.py`). Since these directories are configured as Python packages (with `__init__.py` files), calling these scripts directly as modules (e.g. `from tools.validators.stale_detector import detect_stale_stages`) avoids spawning a new Python process and parsing Python text output, yielding a measurable performance boost. However, one must ensure the Python API is used correctly as many scripts are originally designed as CLI tools.
**Action:** When invoking internal Python utilities from another Python file in this project, prefer direct module imports over `subprocess.run` to save execution time. Always verify that the programmatic API exists and matches what the orchestration expects.

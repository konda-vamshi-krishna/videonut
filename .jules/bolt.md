## 2024-11-11 - Direct Python Module Imports over Subprocess Execution
**Learning:** In a heavily orchestrated Python workflow pipeline (like `workflow_orchestrator.py`), invoking sub-tools using `subprocess.run([sys.executable, script_name])` introduces significant overhead per call due to interpreter startup.
**Action:** Replace `subprocess.run` with direct module imports where target scripts provide clean API returns (e.g. `output_validator.py`, `stale_detector.py`). Crucially, do NOT apply this blindly: scripts relying purely on side effects (like `print`) to stdout without clean return APIs (like `auto_rework.py`) must remain as subprocesses or undergo significant refactoring first. Ensure `sys.path.insert(0, current_dir)` is used to properly resolve `tools` module paths.
